# K8s Quest v0.4 重构方案 - Loop Engineering

> PM: 🍒 樱桃 | 日期: 2026-07-15 | 目标: v0.3 → v0.4 知识教学 + 真实集群

---

## 一、问题诊断

### Master 指出的两个核心问题

1. **没有教学环节**：当前只有"上来就写 YAML 闯关"，学员不知道知识点是什么就被要求做题
2. **没有真实集群**：纯模拟器无法让学员理解 K8s 资源在真实集群中的行为

### v0.3 → v0.4 的差距

| 维度 | v0.3（当前） | v0.4（目标） |
|---|---|---|
| 教学模式 | 直接做题 | 知识讲解 → 示例演示 → 动手练习 |
| 集群类型 | 纯 YAML 模拟器 | 模拟器 + 可选真实 K8s 集群 |
| 反馈方式 | YAML 校验通过/失败 | 真实 Pod 运行状态 / Service 可达性 / 日志 |
| 前端展示 | JSON 集群状态 | kubectl get 风格的资源列表 + Pod 日志流 |

## 二、架构设计

### 2.1 双模式架构

```
学员打开关卡
     ↓
关卡有"教学模式"和"练习模式"
     ↓
教学模式：知识点讲解（图文） + 代码示例 + 交互式演示
     ↓
练习模式：
  ├── 模拟器模式（默认，零依赖）：YAML 校验，虚拟集群状态
  └── 真实集群模式（可选）：部署到真实 K8s，观察真实行为
```

### 2.2 真实集群连接

```
前端 → POST /api/deploy { level_id, user_yaml }
     ↓
后端检测集群模式：
  ├── 模拟器模式：apply_manifest(state, yaml) → 虚拟状态
  └── 真实集群模式：kubectl apply -f yaml → 真实集群
       ↓
       kubectl get pods/services/... → 真实状态
       kubectl logs <pod> → 真实日志
       curl <service-ip>:<port> → 真实请求验证
       ↓
       返回：资源列表 + Pod 状态 + 日志 + 连通性测试结果
```

### 2.3 后端新增 API

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/lesson/{level_id}` | GET | 获取关卡教学文档（知识点讲解+示例） |
| `/api/deploy` | POST | 部署 YAML（模拟器或真实集群） |
| `/api/resources` | GET | 获取当前集群资源列表（真实模式） |
| `/api/logs/{pod_name}` | GET | 获取 Pod 日志（真实模式） |
| `/api/test-connectivity` | POST | 测试 Service 连通性（真实模式） |
| `/api/cluster/status` | GET | 集群连接状态 |

## 五、后端重构

### 5.1 教学文档数据结构

每关增加 `lesson` 字段：

```python
@dataclass
class Lesson:
    concept: str           # 概念讲解（Markdown）
    key_fields: list[dict] # 关键字段 [{name, description, required, example}]
    diagram: str           # ASCII/图示
    example_yaml: str      # 示例 YAML（带注释）
    common_errors: list[str] # 常见错误
    tips: list[str]        # 学习建议
```

### 5.2 集群连接模块

```python
# backend/app/cluster.py
class ClusterManager:
    """真实 K8s 集群管理器"""
    
    def __init__(self, kubeconfig_path: str | None = None):
        self.enabled = kubeconfig_path is not None
        self.kubeconfig = kubeconfig_path
    
    async def apply(self, yaml_text: str) -> dict:
        """kubectl apply -f，返回部署结果"""
    
    async def get_resources(self, resource_type: str) -> list[dict]:
        """kubectl get pods/services/...，返回资源列表"""
    
    async def get_logs(self, pod_name: str) -> str:
        """kubectl logs，返回 Pod 日志"""
    
    async def test_connectivity(self, service_name: str) -> dict:
        """curl Service IP:Port，返回连通性测试结果"""
    
    async def delete_all(self, namespace: str = "default"):
        """清理学员创建的所有资源"""
```

### 5.3 部署模式切换

```python
# backend/app/main.py
DEPLOY_MODE = os.getenv("K8S_QUEST_MODE", "simulator")  # simulator | cluster
CLUSTER_MANAGER = ClusterManager(
    kubeconfig_path=os.getenv("KUBECONFIG")
) if DEPLOY_MODE == "cluster" else None

@app.post("/api/deploy")
async def api_deploy(req: DeployRequest):
    if CLUSTER_MANAGER and CLUSTER_MANAGER.enabled:
        # 真实集群模式
        result = await CLUSTER_MANAGER.apply(req.user_yaml)
        resources = await CLUSTER_MANAGER.get_resources("all")
        return {"mode": "cluster", "deploy": result, "resources": resources}
    else:
        # 模拟器模式（保持现有逻辑）
        result = lv.check_fn(req.user_yaml)
        return {"mode": "simulator", "result": result}
```

## 八、技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 集群连接方式 | subprocess + kubectl | 不引入 python-kubernetes 依赖，保持轻量 |
| 教学文档存储 | Python 数据类（内嵌） | 与关卡代码同目录，版本管理统一 |
| 双模式切换 | 环境变量 K8S_QUEST_MODE | 部署时决定，运行时不变 |
| 集群实战关 | 每章新增 1 关（Q*.5） | 不破坏现有 24 关 |
| 前端 Tab | Alpine.js x-show 切换 | 无需路由，单页应用 |

## 九、风险与缓解

| 风险 | 缓解 |
|---|---|
| Master 环境 kubectl 不可用 | 模拟器模式作为默认，集群模式可选 |
| 集群资源残留 | 每次 deploy 前自动 delete 上一关资源 |
| kubectl 命令超时 | 所有 subprocess 调用设 30s 超时 |
| 教学文档工作量大 | 先做 Ch1 试点，验证模式后批量复制 |
