# K8s 实战学堂 v2.1 架构审视与整改计划

> PM: 樱桃 | 日期: 2026-08-08
> 目标: 从代码倒推设计，识别架构缺陷，评估市场适配度，自主迭代开发

## 审视维度

### 1. 架构审视（架构师 Agent）
- 从代码实现倒推设计意图和架构决策
- 识别设计缺陷（耦合度/扩展性/可维护性/安全性）
- 评估模拟器架构是否支撑未来扩展
- 评估 API 设计是否合理
- 评估前端架构是否能支撑更复杂的交互
- 对每个缺陷评分（P0/P1/P2）+ 修复建议

### 2. 产品/市场适配审视（产品 Agent）
- 评估"新员工快速上手 K8s 实战"目标的达成度
- 学习路径是否合理（从 Q0.1 到 Q28.5 的认知递进）
- 难度曲线是否平滑
- 交互式终端是否真正提升了学习效果
- 模拟器 vs 真实集群的边界是否清晰
- 对校招生的可用性测试（开箱即用？文档够不够？）
- 缺失的能力/内容

### 3. 整合整改清单
- 综合架构师 + 产品 agent 的发现
- 按优先级排序
- PM 判断哪些自主决策、哪些升级 Master

## Sprint 分解

### Sprint A: 双维度并行审视（架构师 + 产品）
- 架构师 agent: 逆向代码架构分析
- 产品 agent: 市场适配度评估
- 输出: 缺陷清单 + 评分 + 整改建议

### Sprint B: 整改开发（基于审视结果）
- Engineer agent: 修复 P0/P1 缺陷
- PM: 自主决策非重大问题

### Sprint C: QA 攻击测试
- QA agent: 5 维度攻击测试
- Fix loop: Engineer 修复 QA 发现的 bug

### Sprint D: 验证 + 推送 + 汇报

## 升级 Master 的条件
- 架构方向性变更（如重写模拟器内核）
- 商业模式/用户影响（如收费、用户系统）
- 不可逆操作（如删除现有章节）
- 跨项目决策
