## 一、产品定位（Why）

**一句话**：通过游戏化模拟器闯关，让 K8s 初学者在浏览器里 30-60 分钟跑通"Pod → Deployment → Service → ConfigMap → Storage → Scheduling"完整闭环，零环境配置，像打游戏一样上头。

### 与竞品对比

| 维度 | Killercoda | KodeKloud | **k8s-quest** |
|------|-----------|-----------|---------------|
| 后端 | 真实 K8s 集群 | 真实集群 | **状态机模拟器** |
| 单用户成本 | $5-15/月 | $39/月 | **¥0** |
| 启动时间 | 30-60秒 | 20-30秒 | **<100ms** |
| 游戏化 | 无 | 基础徽章 | **XP/连击/称号/结业报告** |
| 结业报告 | 无 | 基础 | **知识域分析+薄弱项识别** |
| 故障域 | 集群挂全平台挂 | 同左 | **零**（无外部依赖） |
| 目标人群 | 中高级 | 初-中级 | **初学者** |

### 核心差异化

1. **游戏化上头体验**：不是枯燥的教程，而是像打游戏一样有即时正反馈
2. **结业报告**：学员知道哪里薄弱，导师知道学员完成情况
3. **零成本零配置**：纯浏览器，Docker 一键部署

## 三、技术架构（How）

### 核心机制：YAML 模拟器

```
用户输入 YAML
     ↓
[Parser] yaml.safe_load_all() 解析为 Python dict（支持多文档）
     ↓
[Validator] 跟关卡期望规则比对
     ↓
[Simulator] 应用到虚拟集群状态（Pod/Deployment/Service/ConfigMap/Secret/PV/PVC）
     ↓
[Renderer] 输出新的集群状态 + 解释
```

### API 设计

| 端点 | 方法 | 用途 | v0.3 新增 |
|------|------|------|-----------|
| `/api/health` | GET | 健康检查 | |
| `/api/levels` | GET | 关卡列表 | |
| `/api/level/{id}` | GET | 关卡详情 | ✅ 含知识点+XP |
| `/api/check` | POST | YAML 答案校验 | |
| `/api/meta` | GET | 游戏化元数据 | ✅ 新增 |
| `/api/report` | POST | 结业报告生成 | ✅ 新增 |

### 数据流

1. 用户打开页面 → 前端从 localStorage 恢复进度
2. 前端 GET /api/meta → 获取章节/知识点/XP/称号配置
3. 前端 GET /api/levels → 渲染关卡地图
4. 用户点击关卡 → GET /api/level/{id} → 渲染关卡详情
5. 用户编辑 YAML → 点"运行" → POST /api/check → 显示结果
6. 通过后 → 更新 localStorage → XP/连击/徽章更新 → 动画反馈
7. 用户点"查看报告" → POST /api/report → 展示结业报告

## 四、游戏化系统设计

### XP 与称号

| 总 XP | 称号 | 对应阶段 |
|-------|------|----------|
| 0 | 🎓 K8s 萌新 | 刚开始 |
| 40 | 🌱 Pod 学徒 | 完成 Ch1 |
| 100 | 🚀 Deployment 行者 | 完成 Ch1-2 |
| 180 | 🔗 Service 武者 | 完成 Ch1-3 |
| 260 | ⚙️ 配置大师 | 完成 Ch1-4 |
| 340 | 💾 存储宗师 | 完成 Ch1-5 |
| 420 | 🎯 调度贤者 | 完成 Ch1-6 |
| 500 | 👑 K8s 传奇 | 全部通关+额外挑战 |

- 每关 +10 XP
- 章节全通关 +50 XP
- 满级 500 XP（24关 × 10 + 6章 × 50 = 540，含首通奖励）

### 徽章系统

| 徽章 | 名称 | 获得条件 |
|------|------|----------|
| 🌱 | Pod 新手 | 完成 Ch1 全部 4 关 |
| 🚀 | Deployment 大师 | 完成 Ch2 全部 4 关 |
| 🔗 | Service 老司机 | 完成 Ch3 全部 4 关 |
| ⚙️ | 配置专家 | 完成 Ch4 全部 4 关 |
| 💾 | 存储达人 | 完成 Ch5 全部 4 关 |
| 🎯 | 调度贤者 | 完成 Ch6 全部 4 关 |
| ⭐ | 一击必杀 | 某关一次通过（无失败尝试） |
| 💪 | 百折不挠 | 某关尝试 3 次以上才通过 |
| ⚡ | 速通达人 | 某关 60 秒内完成 |
| 👑 | K8s 传奇 | 全部 24 关通关 |

### 连击系统

- 连续通过（不失败）→ 连击 +1
- 失败 → 连击归零
- 连击 ≥ 3 → 🔥 火焰特效
- 记录最高连击

### 即时正反馈设计（"上头"机制）

**设计理念**：借鉴游戏设计的"核心循环"——行动→反馈→奖励→下一个目标

1. **行动**：用户提交 YAML
2. **即时反馈**：<100ms 返回结果（纯计算，无网络延迟感）
3. **奖励**：+XP 动画、连击计数、徽章解锁、樱桃鼓励语
4. **下一个目标**：显示下一关预览，激发"再玩一关"心理

## 五、结业报告设计

### 报告内容

1. **成绩评定**：S/A/B/C/D 五级
   - S: 100% 完成 + 20关以上首通
   - A: 90%+ 完成
   - B: 70%+ 完成
   - C: 50%+ 完成
   - D: <50% 完成

2. **知识域掌握度**：5 大知识域的完成率
   - 工作负载管理（Ch1-2, 8关）
   - 网络与服务（Ch3, 4关）
   - 配置与密钥（Ch4, 4关）
   - 存储管理（Ch5, 4关）
   - 调度与资源（Ch6, 4关）

3. **薄弱项识别**：未完成或多次尝试的关卡 + 关联知识点

4. **优势项**：一次通过的关卡

5. **学习建议**：基于完成情况的个性化推荐

6. **导出功能**：可下载为 HTML 文件，方便分享给导师

### 导师视图

导师通过学员导出的报告 HTML 可以看到：
- 学员完成进度（X/24）
- 各知识域掌握度
- 薄弱环节
- 总用时和尝试次数
- 成绩等级

## 六、Loop Engineering 开发流程

本项目使用三层 Loop Engineering 架构：

| 层级 | 角色 | 职责 | 终止条件 |
|------|------|------|----------|

| 攻击循环 | QA | 生成攻击用例→发现bug→修复 | 3轮无bug |
